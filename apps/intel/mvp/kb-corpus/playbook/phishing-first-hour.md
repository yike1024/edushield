# 钓鱼邮件事件 · 首小时响应清单

> 适用于已确认收到钓鱼邮件、可能已点击的员工报告或监控告警。严格遵循
> ATT&CK T1566（Phishing）战术编号。

## T+0 ~ T+5min · 隔离与止血

1. **隔离受影响主机**
   - EDR / 终端管理平台 → 网络隔离（不要立即关机，保留内存证据）
   - 拔除主机网络（Wi-Fi / 网线），保留电源
2. **冻结受影响账户**
   - AD / IdP → 立即禁用该账户，吊销所有 session
   - 强制 MFA token 失效（重置）
   - 检查该账户在所有 SaaS 应用中的活跃 session，全部吊销
3. **封禁投递源**
   - 邮件网关 → 加入发件人/发件域黑名单
   - 搜索全公司收件箱：同主题/同发件人/同附件哈希/同 URL，批量隔离

## T+5 ~ T+15min · 证据采集（先采集再分析）

1. **邮件取证**
   - 原始邮件（含完整 .eml 头、附件）
   - 邮件网关日志（投递时间、IP、SMTP 轨迹）
2. **终端取证**
   - EDR 进程树（看可疑进程父子关系）
   - DNS 日志（看是否解析过可疑域名）
   - PowerShell / Bash 历史
   - **不重启主机**，保留内存取证可能
3. **身份取证**
   - IdP 登录日志、VPN 登录日志
   - SSO 票据发放记录
   - OAuth 应用授权列表（防 Illicit Consent Grant - T1556）

## T+15 ~ T+45min · 影响评估

| 检查项 | 命令 / 工具 |
|---|---|
| 是否点击附件？ | EDR 进程创建、文件创建 |
| 是否输入凭据？ | 浏览器密码数据库变化 / 表单提交记录 / cookie 写入 |
| 是否触发宏？ | Office 进程派生 PowerShell / mshta / wscript |
| 是否下载二级载荷？ | 网络流量 EDR / DNS 解析异常 |
| 是否横向移动？ | 异常 SMB / WMI / WinRM / RDP 行为 |
| 是否访问邮件联系人？ | Outlook/MAPI 调用记录 |

## T+45 ~ T+60min · 通报与升级

- 向公司管理层 + 法务 + 合规通报（**分级报告**）
- 若涉及**个人信息泄露**或**监管机构要求**，按 PIPL / DSL 启动合规流程
- 若涉及**关键信息基础设施**，按《关基条例》第 18 条 **24 小时内**报保护工作部门
- 准备攻击者画像：T1566.001（附件钓鱼） / T1566.002（链接钓鱼） /
  T1566.003（通过服务投递） / T1566.004（鱼叉鱼叉）

## 后续阶段（60min+）

- 资产层：清查受影响邮箱、终端、账户、文件
- 数据层：取证邮件附件、URL、可能的下载物
- 处置层：清除恶意持久化、重置凭据、补丁
- 复盘层：72h 内出 first timeline，2 周内出 full postmortem
- **沉淀**：postmortem 全文通过 `mcp__seckb__kb_ingest` 写入 internal 集合

## 常见误区

- ❌ 立即关机 → 丢失内存证据
- ❌ 只查账户 → 漏掉 SaaS session、OAuth 应用、API token
- ❌ 忽略 Outlook 规则 → 攻击者经常建"删除所有来自 IT 部门的邮件"规则
- ❌ 不追踪附件哈希 → 同一附件会再次投递
- ❌ postmortem 不入库 → 下次同类攻击重复踩同样的坑
