# 网络安全等级保护 2.0 三级技术要求

## 适用范围

本要点适用于**网络安全等级保护三级**系统的安全建设和整改。三级系统一般
为**地市级以上重要行业**的关键信息基础设施或重要数据处理系统，覆盖
党政机关、金融、电信、能源、交通、水利、医疗、教育等行业中的核心业务。

> 注：以下条目为技术要求（安全通信网络 / 安全区域边界 / 安全计算环境 /
> 安全管理中心）摘录，**完整条文以 GB/T 22239-2019 原文为准**。

## 安全通信网络

| 控制点 | 三级要求 | 实测关注 |
|---|---|---|
| 网络架构 | 关键网络节点提供硬件冗余，保证网络可用性 | 双机热备、链路聚合 |
| 通信传输 | 关键数据采用密码技术进行保密性和完整性保护 | TLS 1.2+、国密 SM2/SM4 |
| 可信验证 | 基于可信根对通信设备的系统引导程序、系统程序等进行可信验证 | TPM 2.0、可信启动 |

## 安全区域边界

| 控制点 | 三级要求 |
|---|---|
| 边界防护 | 跨越边界的访问和数据流通过受控接口进行；非授权设备不得接入内部网络 |
| 访问控制 | 在网络边界或区域之间根据访问控制策略设置访问控制规则，默认拒绝 |
| 恶意代码防范 | 在关键网络节点处对恶意代码进行检测和清除，并维护恶意代码防护机制的升级和更新 |
| 入侵防范 | 在关键网络节点处检测、防止或限制从外部发起的网络攻击行为 |

## 安全计算环境

| 控制点 | 三级要求（节选） |
|---|---|
| 身份鉴别 | 采用两种或两种以上组合的鉴别技术对用户进行身份鉴别（**双因子**） |
| 访问控制 | 主体对客体的访问权限最小化；授权主体配置访问控制策略 |
| 安全审计 | 记录系统中的重要用户行为和重要安全事件；审计记录保护防止删除修改；**审计记录留存 ≥ 6 个月** |
| 入侵防范 | 能发现已知漏洞、能够在检测到入侵时记录入侵的源 IP/攻击类型/目标；**最小化部署原则** |
| 恶意代码防范 | 采用免受恶意代码攻击的技术措施或主动免疫可信验证机制 |
| 数据完整性 | 采用校验技术或密码技术保证重要数据在传输过程中的完整性 |
| 数据保密性 | 采用密码技术保证重要数据在传输过程中的保密性 |
| 数据备份恢复 | 提供重要数据的本地与异地备份；**关键业务 4 小时 RPO、8 小时 RTO** |

## 安全管理中心

| 控制点 | 三级要求 |
|---|---|
| 系统管理 | 通过安全管理员对系统中的安全策略配置进行集中管理 |
| 审计管理 | 通过安全审计员对审计记录进行分析、生成报表 |
| 安全管理 | 通过安全管理员对安全设备 / 安全相关组件进行集中管控 |

## 渗透测试要点（自查清单）

- [ ] 双因子登录：ssh / RDP / VPN / 数据库账号是否全部启用
- [ ] 默认拒绝：防火墙出/入站策略是否显式 deny-by-default
- [ ] 审计留存：syslog、数据库审计、应用日志是否 ≥ 180 天
- [ ] 漏洞闭环：最近一次全量漏洞扫描的**高危**是否 30 天内修复
- [ ] 国密合规：对外数据传输是否使用 TLS 1.2+，政务类是否使用国密
- [ ] 异地备份：备份介质是否物理异地存放，年度恢复演练是否完成

## 常见判项误区

- ❌ "用了 SSL 就够了" —— TLS 1.0/1.1 已不允许
- ❌ "有日志就算审计" —— 必须集中收集 + 防篡改 + 留存时长达标
- ❌ "有 WAF 就防入侵了" —— 入侵防范还要求检测未知 / 已知漏洞
- ❌ "双因子 = 短信 + 密码" —— 短信已被弱化为非主要因子
