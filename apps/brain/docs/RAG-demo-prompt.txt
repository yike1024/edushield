【任务】请帮我在你的前端工程里做一个“AiSOC 安全知识库 RAG 检索 Demo”页面，用于对外展示本地安全知识检索效果。
它调用后端已就绪的一个只读检索接口，输入一个问题，返回并展示命中的安全知识条目（含条目内容与相似度分数）。

────────────────────────────────────────
一、后端接口（已就绪，直接调用即可，无需后端配合）
────────────────────────────────────────
接口：GET  http://127.0.0.1:6657/api/rag/search
参数：
  q  （必填，URL 编码后的中文/英文查询问题）
  k  （可选，返回条数，默认 5，最多 20）
CORS：已全开（allow_origins=*），跨域可直接 fetch，无需代理。

调用示例：
  fetch('http://127.0.0.1:6657/api/rag/search?q=SQL注入怎么防御&k=5')

返回 JSON 结构：
{
  "query": "SQL注入怎么防御",
  "k": 3,
  "hits": [
    {
      "content": "SQL注入：攻击者在输入中插入恶意SQL操纵数据库。防御：参数化查询、预编译语句、输入验证、最小权限数据库账户。",
      "score": 4.0
    },
    { "content": "XSS跨站脚本：……", "score": 4.0 }
  ]
}
字段说明：
  query : 原始查询
  k     : 请求条数
  hits  : 检索命中条目，按相关度降序；score 为该条的相关性分（越高越相关）

────────────────────────────────────────
二、Demo 页面应做成什么样
────────────────────────────────────────
1) 顶部标题：如「AiSOC 安全知识库 RAG 检索」。可配一行小字说明：输入安全类问题，命中本地内置知识库（5 大域：Web 攻击/攻防技战术/漏洞/等保合规/校园场景）。
2) 输入区：一个文本框 + 「检索」按钮；支持回车触发；可配 2-3 个“示例问句”快捷按钮（一键填入检索），建议示例：
   · SQL注入怎么防御
   · Log4j 漏洞应该怎么处理
   · 被拖库、学生信息泄露怎么办
3) 结果区：逐条渲染 hits，每条建议显示内容 + 右侧/下方一个相关度分数（如“相关度 4.0”，或用进度条直观展示 score/max）。
4) 空状态/加载：检索中给 loading；q 为空或 hits 为空时给友好提示（“未命中本地知识，可换一种问法”）。网络出错显示错误信息。
5) 底部可加一句演示口径（对观众）：检索是本地离线向量库，不给模型改 prompt、不调用模型，只返回相似知识召回 —— 以体现“知识库端到端检索”已在后端可用。

────────────────────────────────────────
三、演示场景文案建议（你可以在页面上贴给观看者）
────────────────────────────────────────
- “针对威胁/漏洞/合规问题，系统可在本地安全知识库快速召回相关处置建议与依据。”
- “演示输入：教务系统遭 SQL 注入怎么办 → 系统召回参数化查询/输入校验/最小权限账户等修复要点。”
- “本 Demo 仅展示检索层能力；完整能力还会把召回结果注入到智能体对话与威胁判定中作为参考依据。”

────────────────────────────────────────
四、边界与注意
────────────────────────────────────────
- 本接口只读、不写库、不消耗模型 token，可放心频繁演示。
- 检索是“关键词/轻量本地向量”的召回，对长句会分片打分；个别并列分属正常，不必过度解释。
- 若为演示整理，可在页面上一次性发起 3 个示例并行对比命中差异，观感更直观。
