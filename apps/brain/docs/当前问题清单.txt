二、P0 阻塞：RAG 检索不可用（chromadb 兼容 bug）
====================================================
现象：
    GET /api/rag/search?q=SQL注入&k=1
    → {"error":"检索失败: 'str' object is not callable"}
    启动日志：WARNING: [RAG] 后台播种异常: 'str' object is not callable
根因（已定位）：
    chromadb 1.5 与自写 embedding 对象的**持久化配置不兼容**——
    chroma_data/ 里 collection 记录的 embedding 配置，在新进程反序列化时
    被当作可调用对象调用（实际是 str）→ 抛错。
    9/8 首次建库的那个进程可用；此后**每次重启都失败**。
历史绕法（不可持续）：删掉 chroma_data 重建 → 当次可用，下次重启又坏。
影响：RAG 检索端点、对话知识注入、verdict 的 rag_knowledge 注入全部空转。
说明：此问题在 9/8 就已存在，当时用"重建库"临时绕过，**未根治**；
      9/19 用户明确选择"先不动 RAG"，故保持现状。
可选修法（待用户决定）：
    A) 彻底弃用 chroma 的向量能力，seed 33 条知识改存本地 JSON，
       检索走已实现的 _keyword_scores 关键词打分
       （推荐：我们本来就不用 chroma 的向量检索，摆脱兼容坑，重启必好）
    B) 保留 chroma，启动时检测配置不兼容则自动重建 collection + 重灌 seed
    C) 继续不管
